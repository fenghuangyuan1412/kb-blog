# PRD —— 个人博客 / 知识库

## 1. 目标

把我散落在各处的四类内容（项目、算法、想法、笔记）收进一个能自己写、能公开读、能全文搜索的地方。
它是学习成果的归档处，也是投简历时能直接打开链接的作品集。

衡量标准（做完怎么看它成不成）：

- 我能在 30 秒内从后台发一篇笔记，并立刻在前台看到它
- 一篇嵌套在三层目录里的笔记，能在左侧树里点开后正常渲染
- 搜一个只在正文里出现的词，能找到对应文档
- 从任何一台设备的浏览器访问，不需要本地起服务

## 2. 用户

| 角色 | 数量 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 访客 | 不限 | 浏览四类内容、全文搜索、按标签过滤、在笔记树里跳转 | 写任何东西、看到后台 |
| 我（管理员） | 1 | 访客全部能力 + 登录后台增删改文档、设置笔记父子关系和排序 | 无（全站最高权限） |

## 3. 功能清单

### 阅读侧（公开）

- F1 首页：自我介绍 + 精选项目 + 最近笔记
- F2 项目集：卡片列表，按标签过滤，详情页展示 `meta.repo` / `meta.demo` / 技术栈 / 状态 / 起止时间
- F3 算法：表格列表（名称、时间/空间复杂度、标签、语言），详情页 Markdown + 代码高亮
- F4 想法：时间线列表，允许草稿态（`status=draft` 时仅后台可见）
- F5 笔记：左侧无限层级可折叠树 + 右侧 Markdown 正文，支持 `/notes/:slug` 直接定位
- F6 标签页：`/tags/:tag` 聚合四类内容
- F7 搜索：`q` 走 `tsvector`（`simple` 配置，中文按词条/英文按词），支持限定 `type`
- F8 SEO：每篇文档输出 title / description / 规范链接

### 后台侧（需认证）

- F9 登录 / 登出：JWT 存 httpOnly Cookie，凭据来自 `.env`，无注册
- F10 文档列表：按 `type` / `status` 筛选，能删除
- F11 编辑器：左侧 Markdown 输入、右侧实时预览，可设 `type` / `slug` / `summary` / `tags` / `status` / `sort_order` / `meta`
- F12 父子选择器：`note` 类型可从笔记树里选父节点；`move` 接口支持改父节点和排序
- F13 slug 冲突时给出明确报错，不静默覆盖

## 4. 明确不做（这一栏比功能清单重要）

- 不做用户注册、找回密码、多角色权限
- 不做评论区（想反馈的人给我发邮件）
- 不做访问统计 / 点赞 / 阅读量
- 不做富文本所见即所得编辑器，只写 Markdown
- 不做附件上传 / 图床（图片走外链）
- 不做多语言 i18n
- 不做草稿版本历史、协同编辑、定时发布
- 不引入 Redis / Kafka / 微服务 / GraphQL / gRPC / K8s
- 不做 Elasticsearch：全文搜索用 PostgreSQL 的 `tsvector` + GIN 索引

## 5. 时间盒

三天冲刺。Day 1 后端端到端可 curl，Day 2 前台可浏览，Day 3 后台可写 + 上线。
任何功能在当天做不完，就按 `project-dev` Skill 的要求记录「未完成 + 原因 + 下一步」，不许留 TODO 占位。

## 6. 风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 中文全文搜索用 `simple` 配置效果有限（不按中文分词） | 搜中文词可能漏 | 先保证 title/summary 命中；若不可用再评估 `zhparser`，属技术栈变更需先议 |
| 免费部署额度（Fly.io / Vercel / Neon）冷启动慢 | 首次访问慢 | Day 3 记录实测，必要时只保前端在线 |
| 时间盒紧，后台编辑器容易超期 | 上线延期 | 编辑器最简可用（textarea + 预览），排版优化留到冲刺后 |
